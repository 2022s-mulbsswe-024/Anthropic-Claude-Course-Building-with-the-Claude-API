 16 BM25 lexical search:
 Step 1: Tokenize the query
Break the user's question into individual terms. For example, "a INC-2023-Q4-011" becomes ["a", "INC-2023-Q4-011"].

Step 2: Count term frequency
See how often each term appears across all your documents. Common words like "a" might appear 5 times, while specific terms like "INC-2023-Q4-011" might appear only once.

Step 3: Weight terms by importance
Terms that appear less frequently get higher importance scores. The word "a" gets low importance because it's common, while "INC-2023-Q4-011" gets high importance because it's rare.

Step 4: Find best matches
Return documents that contain more instances of the higher-weighted terms.

If we mix both VectorIndex and BM25 the result are more better
Here are 4 lines explaining how this hybrid work pipeline operates:

* **Dual Search Execution:** A single query is sent simultaneously to a **Vector Index** (for semantic meaning) and a **BM25 Index** (for exact keyword/ID matching).
* **Unified Interface:** A coordinator class called a `Retriever` standardizes both search engines under a single `search()` method to keep the code modular.
* **Rank Fusion Calculation:** It uses **Reciprocal Rank Fusion (RRF)** to score documents based on their position in both lists, ensuring items that perform well in both systems rise to the top.
* **Contextual Accuracy:** By merging both approaches, it solves vector search's blind spots—like missing specific product codes or ticket IDs—while retaining its deep understanding of natural language.
RRF_score(d) = Σ(1 / (k + rank_i(d)))

22. Code execution and file api
Files API
The Files API provides an alternative way to handle file uploads. Instead of encoding images or PDFs directly in your messages as base64 data,
 you can upload files ahead of time and reference them later.
 
 Code Execution Tool
Code execution is a server-based tool that doesn't require you to provide an implementation. You simply include a predefined tool schema in your request, and Claude can optionally execute Python code in an isolated Docker container.


1.The Courier Upload:Files API.You upload your raw data (like streaming.csv) using the Files API. The system takes the file, stores it securely, 
and hands you a unique File ID (like a tracking number).2.The Work Order:Anthropic API Call.You send a message to Claude. In this message, 
you bundle two things: your instructions ("Find out why users are canceling!") and the File ID from Step 1. You also explicitly
 turn on the code_execution tool.3.Entering the Lab:Isolated Container.Claude takes your File ID and enters the isolated lab. The system automatically
 places your CSV file inside this lab so Claude can reach it.4.The Brainstorm & Execution:Iterative Python Coding.Claude writes Python code to 
 read the CSV, calculate statistics, and generate a plot. It runs the code, looks at the errors or results, and might rewrite and rerun the 
 code multiple times until the analysis is perfect.5.The Hand-off:Downloading Results.Claude steps out of the lab and hands you a text response,
 alongside a new Output File ID for the chart it created. You use the Files API one last time to download that chart to your computer.

 23. MCP Model Context Protocol
 MCP shifts the burden of tool definitions and execution from your server to MCP servers. 
 Instead of you writing, testing, and maintaining complex custom code (schemas and functions) to connect an AI to an outside service (like GitHub or AWS),
 an MCP Server does that work for you. It acts as a pre-built wrapper around an API.
 Anyone or any company (like AWS) can build an MCP server. Once created, any AI application can connect to it and instantly gain access to those tools.
 MCP doesn't replace tool use; it replaces the work of building the tools. It gives you pre-defined tool schemas and functions
 so you don't have to code them from scratch.
